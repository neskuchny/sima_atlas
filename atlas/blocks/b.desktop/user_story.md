# b.desktop — user_story

## User Story 1 — оператор без терминала

**Как** разработчик продукта, который слышал про Sima Atlas в Twitter'е,
**когда** я зашёл на страницу релиза, увидел три кнопки (Mac · Windows ·
Linux) и скачал ту, что подходит моей ОС,
**я хочу** двойным кликом получить рабочее окно с канвасом, моим первым
проектом (или demo) и нативным меню — **без** установки Node, npm, или
запуска `git clone`,
**чтобы** провести первые 10 минут в продукте, а не в борьбе с тулчейном.

## User Story 2 — multi-project на одном компьютере

**Как** оператор, который ведёт три параллельных продукта (свой стартап,
консалтинг для клиента, side-проект),
**когда** я открываю File → Open Project, я вижу список папок из
`~/SimaProjects/`,
**я хочу** переключаться между ними одним кликом и видеть для каждого
свой канвас, свою экономику, свой V-1-лог,
**чтобы** не путать контракты разных продуктов и иметь чёткую границу
конфиденциальности.

## User Story 3 — auto-update

**Как** оператор, у которого установлена v0.3.0,
**когда** разработчики Sima выпускают v0.4.0 с новыми фичами,
**я хочу** при следующем запуске увидеть нативную нотификацию «обновление
доступно — установить?», ОК скачивает в фоне и заменяет приложение при
ребуте,
**чтобы** мой апдейт-флоу был похож на VS Code или Cursor, а не на
«ой, надо опять git pull и npm install».

## User Story 4 — нативное меню = быстрые действия

**Как** оператор, который ночью гоняет V-1, а днём правит контракты,
**когда** я в окне приложения нажимаю ⌘+Shift+R (или Ctrl+Shift+R),
**я хочу** запустить ночной V-1-цикл из меню Run → V-1 Autonomous Loop с
дефолтным budget cap'ом и max-iterations, без необходимости открывать
терминал и помнить полный CLI-вызов,
**чтобы** ежедневный workflow был на расстоянии хоткея.
