## User Stories

**Как** архитектор Атласа / **Когда** я хочу автоматически извлекать блоки из диалогов / **Я хочу**, чтобы LLM-шлюз предоставлял структурированный вывод блоков на основе JSON Schema / **Чтобы** ускорить создание и поддержку актуальной структуры Атласа.

**Как** разработчик / **Когда** я работаю с LLM в Атласе / **Я хочу** иметь единую точку входа для вызовов LLM с абстракцией от конкретного провайдера / **Чтобы** упростить интеграцию и переключение между различными LLM-провайдерами.

**Как** CI / golden set eval / **Когда** мне нужно протестировать функциональность, зависящую от LLM / **Я хочу** использовать mock-провайдер LLM-шлюза / **Чтобы** обеспечить детерминированные результаты и избежать зависимости от внешних API.

**Как** инженер по надежности / **Когда** я хочу отслеживать использование LLM в Атласе / **Я хочу**, чтобы каждый вызов LLM логировался с информацией о провайдере, модели, стоимости и ошибках / **Чтобы** иметь возможность анализировать и оптимизировать использование LLM.

**Как** администратор / **Когда** я хочу контролировать расходы на LLM / **Я хочу** иметь возможность устанавливать лимиты на количество токенов и стоимость каждого запуска LLM / **Чтобы** избежать непредвиденных расходов.

**Как** пользователь Атласа / **Когда** основной LLM-провайдер недоступен / **Я хочу**, чтобы LLM-шлюз автоматически переключался на mock-провайдер / **Чтобы** функциональность, зависящая от LLM, продолжала работать.

**Как** разработчик / **Когда** я хочу интегрировать извлечение блоков из диалога в Атлас / **Я хочу** использовать sugar-функцию `extractBlockSchema(dialogText)` / **Чтобы** упростить процесс извлечения и создания блоков.

**Как** разработчик / **Когда** я хочу убедиться, что LLM-шлюз работает корректно / **Я хочу** иметь набор KPI для оценки качества работы шлюза / **Чтобы** обеспечить стабильность и надежность работы LLM-шлюза.
