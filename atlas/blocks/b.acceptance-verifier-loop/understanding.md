# b.acceptance-verifier-loop — understanding

_Объявлено исполняющим агентом до кода (R-8.11: кэш верификатора и KPI-2).
Заголовки английские — их читает машина; содержание на языке миссии._

## Treating this as

Кэш сборки с консервативным ключом, как у инкрементальных систем сборки:
результат проверки блока переиспользуется, только если не изменилось
ничего, от чего он зависит, — а «от чего зависит» определяется по замеру,
а не на глаз. Промах всегда безопасен (проверка просто выполняется);
попадание допустимо, только когда ключ покрывает все входы. Кэш, который
вернул «pass» после реального изменения, — это тот самый тихий зелёный.

## In scope

- Ключ = код (git HEAD + содержимое изменённых и новых файлов вне atlas/) +
  контракты всех блоков и graph.json + сводка вердиктов всех блоков
  (последний результат, без меток времени) + явные цели log_grep / fs_glob /
  file_diff этого блока + режим LLM + версия node.
- Кэшируется `pass`; «не определено» — только под принудительным моком (там
  судья не спрашивается, результат детерминирован; режим LLM в ключе, живому
  прогону такая запись не отдаётся); `fail` не кэшируется никогда —
  случайный таймаут не должен прилипнуть на сутки. Ни один закэшированный
  вердикт не может оказаться ложным зелёным.
- Ключ записывается после собственных записей верификатора, поэтому его же
  вывод не сбрасывает кэш.
- Промах называет причину: что именно изменилось.
- Без git (установленное десктоп-приложение) кэш выключен и так и говорит.
- Отключение: `--no-cache` / `ATLAS_VERIFY_CACHE=0`; срок жизни 36 ч.
- KPI-2: пять проверок с LLM-судьи на настоящие детерминированные тесты.
- R-8.12 (из Spec Kit converge): список «что доделать» живого
  семантического судьи дописывается в `tasks.md` отмечаемыми задачами под
  разделом «Convergence» — только дописывается, повторы не дублируются,
  ничего не удаляется. Под моком судья ничего не требует и ничего не пишет.

## Out of scope

- Демо-блоки продукта (`b.product-*`): кода нет, честно перевести нечего.
- A8 этого блока: в тексте есть pre-commit hook, которого нет; переводить
  её — значит сразу получить честный провал; остаётся за судьёй.
- Кэш для llm_judge-проверок на живой модели сверх общего ключа.

## Variant chosen

- Кэш в `verifyBlock` (общая точка для nightly, гейта, демона), запись — в
  вызывающих после их записей.
- Производные артефакты (wiki, roadmap, sync_report) и рабочие логи вне
  ключа: они — функция ключевых входов плюс время. Если блок явно проверяет
  такой файл, он входит в ключ этого блока.

_Изменено по ходу работы: сначала кэшировался только `pass`, но тогда
демо-блоки продукта (под моком всегда «не определено») промахивались при
каждом прогоне, хотя их результат детерминирован. Решение дописано выше._

## Assumed without asking

- «В среднем по репо» в KPI-2 считаю как долю всех пунктов приёмки;
  `selftest_run` — вариант `exit_code` (строже), считается детерминированным.
- «Новые traces» из формулировки KPI-6 не входят в ключ: трассы — выход
  вызовов LLM, а не вход проверки; вход судьи — контракт и код, они в ключе.
