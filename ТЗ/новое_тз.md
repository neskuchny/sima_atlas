# Sima Atlas — структура (revised, sync-first)

## 0. Главная проблема, которую система решает

| Проблема | Сегодня | Что делает Sima |
|---|---|---|
| **Рассинхрон кода**: разные сессии ИИ пишут на разных фреймворках/библиотеках, не сходятся между собой | ИИ ничего не помнит про правила проекта | Единый `rules.md` + `tech_stack.md` + связи блоков, которые ИИ читает **до** работы |
| **Невидимый прогресс**: человек не знает что готово, что нет | Надо лезть в код, читать readme разных версий | Визуальная схема: блок зелёный/жёлтый/красный, рядом — список выполненных/невыполненных задач и тестов |
| **Дрейф документации**: Claude пишет один README, Cursor пишет другой, ROADMAP протух | Каждый агент создаёт свои файлы | Один источник истины — папка `/atlas/`, всё остальное автогенерируется из неё |
| **Раздутое контекстное окно**: 80–90% — мусор от прошлых обсуждений и тестов | LLM читает всю переписку | В контекст идёт **только папка нужного блока + его прямые соседи**. Тесты — короткие записи в `checks.log` |
| **Мёртвые файлы**: ИИ натыкается на старый файл и правит его | Файлы не помечены | `files_registry.md` со статусом alive/dead/archived |
| **«Работает, но не то»**: код проходит тесты, но не выполняет изначальный смысл | Смысл потерян | У каждого блока есть `mission.md` + `kpi.md` + `acceptance.md` — тест провален, если KPI не выполнен, даже если код запустился |
| **Cursor забыл всё в новой вкладке** | Перечитывает весь репозиторий | Нужно прочитать только `/atlas/blocks/<id>/` — этого достаточно |

## 1. Главный принцип хранения — **блок-как-папка**

Никаких векторных БД как основной памяти. Память — обычные markdown-файлы, разложенные по структуре. Схема в интерфейсе и папка на диске — одно и то же.

```
/atlas/                         ← ОДИН источник истины
  project.md                    ← миссия, цель, JTBD
  rules.md                      ← правила кода: стиль, запреты, conventions
  tech_stack.md                 ← фреймворки, библиотеки, версии (lock)
  roadmap.md                    ← очерёдность блоков (автогенерится)
  files_registry.md             ← alive | dead | archived + причина
  decisions.log                 ← ADR-формат: дата, решение, причина
  failures.log                  ← что пробовали и почему не пошло
  graph.json                    ← блоки + связи (то, что рисует UI)
  /blocks/
    <block_id>/
      mission.md                ← зачем этот блок (axis)
      kpi.md                    ← как поймём, что работает
      acceptance.md             ← критерии «готово» (smysl, не только runtime)
      logic.md                  ← как должен работать (бизнес-логика)
      frontend.md               ← UI-часть, скрины, стили
      backend.md                ← endpoints, схема данных, ограничения
      depends_on.md             ← какие блоки нужны + что от них берём
      provides.md               ← что даёт другим блокам
      tasks.md                  ← чек-лист, статусы, приоритеты
      checks.log                ← короткие записи: дата, тест, pass/fail, KPI
      decisions.log             ← локальные решения по блоку
      patterns.md               ← что работало / не работало (опыт)
      files.md                  ← какие файлы кода относятся к блоку
      screenshots/              ← визуальное состояние
      history/                  ← прошлые версии mission/logic (diff)
  /artifacts/                   ← переиспользуемые блоки
```

**Зачем это нужно:** чтобы написать любой модуль, ИИ читает 5–10 коротких файлов из одной папки + 2–3 файла из соседних блоков по `depends_on.md`. Это **тысячи токенов, а не сотни тысяч**. Никакого RAG не нужно — путь к нужному знанию определяется графом, а не косинусным сходством.

## 2. Что чем замещаем (откуда берём, как переориентируем)

| Из ТЗ нужно | Что использовать | Как использовать **в этой парадигме** |
|---|---|---|
| Визуальный редактор схем (главный UI) | `Sima (Remix)/arch_canvas.jsx`, `arch_data.js`, `app_v2.jsx`, `layer1..4`, `subschema.jsx`, `gallery_v2.jsx`, `composer.jsx`, `library_view.jsx`, `landscape_view.jsx`, `graph_view.jsx`, `tweaks-panel.jsx` | Берём **полностью**. Это уже готовый конструктор слоёв и блоков. Модель `ARCH_LAYERS / ARCH_LINK_TYPES / ARCH_STATUS` ложится на наш граф 1:1. `localStorage` заменяется чтением `graph.json` и папок `/blocks/<id>/` |
| Snapshot Axis/Character/Memory | `agi_small/core/snapshot.py, axis.py, character.py, models.py` | Берём **модель**, но храним в **markdown**, а не в Neo4j. `axis` → `mission.md + kpi.md`, `character` → `patterns.md`, `memory` → `decisions.log + checks.log + history/` |
| Иерархия U → C → G → E | `agi_small/core/snapshot.py:get_hierarchy` | U = `project.md + rules.md`. C = верхние блоки. G = средние. E = подсхемы. Иерархия — это вложенность папок и поле `parent` в `graph.json` |
| Patch-обновление снэпшота | `agi_small/modules/snapshot_diff.py, snapshot_update_analyzer.py, core/snapshot_dedup.py` | После каждого ответа ИИ — diff к нужному `.md` и запись прошлой версии в `history/`. Никогда не переписываем целиком |
| Извлечение фактов/принципов из чата | `modules/principle_extractor.py, pattern_engine.py, concept_crystallizer.py, wisdom_distiller.py` | Берём — но **только для того, чтобы дописать `patterns.md`, `decisions.log`, `rules.md`**. Сама переписка с ИИ в долгую память НЕ кладётся |
| Детектор противоречий (рассинхрон) | `modules/conflict_resolver.py, retrieval/contradiction_detector.py, core/belief_graph_checker.py, core/ingestion_validator.py` | Главный движок «синхронизировано / нет»: при каждом изменении проверяет, что блок не нарушает `rules.md`, `tech_stack.md`, `provides.md` соседей. Подсвечивает блок красным |
| Gap detector / hypothesis | `modules/gap_detector.py, hypothesis_analytics.py` | Помечает поля карты, которые не заполнены, и пропуски в `acceptance.md` / `kpi.md` |
| Ночная консолидация | `agi_small/batch/nightly.py, scheduler.py, modules/axis_evolution.py, sleep_consolidation.py` | Раз в сутки: пересборка `roadmap.md`, проверка alive/dead файлов, поиск противоречий, обновление `intelligence_health` (= процент синхронизированных блоков) |
| Retrieval router (10 маршрутов) | `agi_small/retrieval/router.py, intent.py, depth_planner.py` | **Понижаем в роли.** Главный «поиск» — путь по графу: `block_id → /blocks/<id>/`. Router нужен **только** для запросов «найди где обсуждали X» по векторной БД эпизодов (бывшие чаты). Это backup-память, не основная |
| Подключение к coding-агентам | Cursor TypeScript SDK + Cursor hooks (`.cursor/hooks.json`) + Claude Code CLI + Codex CLI + Antigravity | Все агенты получают **один и тот же путь** к блоку: `/atlas/blocks/<id>/`. Любой инструмент видит продукт одинаково |
| Идея авто-вики (CodeWiki-style) | концептуально | Wiki = страничный рендер тех же markdown файлов. Один источник — одна правда |

## 3. Что попадает в контекстное окно ИИ (минимизация)

Когда пользователь нажимает «реализуй блок X» в Sima:

```
CONTEXT-PACK (≈ 4–12k токенов)
├── /atlas/project.md            (~300 токенов — миссия)
├── /atlas/rules.md              (~500 — правила кода)
├── /atlas/tech_stack.md         (~200 — стек)
├── /atlas/blocks/X/
│   ├── mission.md               (~150)
│   ├── kpi.md                   (~150)
│   ├── acceptance.md            (~200)
│   ├── logic.md                 (~600)
│   ├── frontend.md или backend.md (~600)
│   ├── tasks.md                 (~400 — что именно сейчас делать)
│   ├── patterns.md              (~300 — чтобы не повторить ошибки)
│   └── files.md                 (~150 — какие файлы относятся к блоку)
├── /atlas/blocks/Y/mission.md   (~150 — Y из depends_on)
├── /atlas/blocks/Y/provides.md  (~150)
└── /atlas/blocks/Z/provides.md  (~150 — Z из depends_on)
```

**Чего там НЕТ:**
- сырых транскриптов чатов
- старых файлов кода, помеченных dead
- логов тестов целиком (только ссылка на `checks.log`)
- блоков, не связанных с X через граф
- README/ROADMAP в произвольных местах репозитория

## 4. Лог тестов и проверок — компактный формат

`checks.log` блока:
```
2026-04-30 14:02  unit/login_form         pass    ms=42
2026-04-30 14:03  e2e/onboarding          fail    «expected 3 шага, было 2»  → task#17
2026-04-30 14:05  kpi/p95_latency<200ms   pass    measured=174ms
2026-04-30 14:07  acceptance/«email-валидация по RFC»  fail  → task#18
```

Это всё, что попадает в контекст — **не разбор теста, не вывод, не stderr**. Если ИИ нужно копнуть — он попросит сам.

## 5. Реестр живых/мёртвых файлов

`files_registry.md`:
```
| path                          | status   | block | reason                          |
|-------------------------------|----------|-------|---------------------------------|
| src/auth/login.tsx            | alive    | b.auth| текущая реализация              |
| src/auth/login_old.tsx        | dead     | b.auth| заменён 2026-04-12, удалить     |
| src/legacy/v1/api.py          | archived | —     | прошлая версия, не трогать      |
| scripts/migrate_2025.py       | archived | —     | разовая миграция                |
```

Перед запуском задачи **первый шаг любого агента** — прочитать эту таблицу. Dead-файлы для него не существуют.

## 6. Проверка синхронизации (sync check)

Это центральная фича. Запускается:
- автоматически после каждого изменения блока
- вручную кнопкой «sync» в Sima
- в ночной консолидации

Что проверяется:

| Проверка | Источник правил | Реализация |
|---|---|---|
| Стек блока совместим с `tech_stack.md` | `tech_stack.md` | grep по `frontend.md / backend.md` блока |
| Блок не нарушает `rules.md` (стиль, запреты) | `rules.md` | LLM-валидатор (короткий prompt: правила + текущий блок → conflict?) |
| `provides.md` блока А покрывает то, что блок Б требует в `depends_on.md` | граф | прямое сопоставление полей |
| Все блоки на пути от `user` → `data` существуют и не red | граф | обход графа |
| KPI всех блоков MVP измерены (есть запись в `checks.log`) | `kpi.md` + `checks.log` | парс файла |
| Acceptance-критерии всех done-блоков проверены | `acceptance.md` + `checks.log` | парс |
| Все файлы из `files.md` блоков либо alive, либо помечены dead и удалены | `files_registry.md` | сверка |
| `roadmap.md` соответствует текущим status блоков | `graph.json` | пересборка |

Результат:
```
SYNC REPORT 2026-04-30
========================
Total blocks: 24
✓ synchronized: 18
⚠ drift:        4   (b.payments, b.notifications, b.search, b.export)
✗ broken:       2   (b.auth – нарушает rules.md§3, b.api – stack mismatch)

→ b.auth: «использован zod, но rules.md§3 запрещает рантайм-валидацию»
→ b.api : «декларирует FastAPI, но tech_stack.md = NestJS»
→ b.payments: depends_on b.auth (broken)
```

В UI Симы это окрашивает блоки и показывает причину **рядом с блоком**, а не в чате.

## 7. UI: что человек делает руками

Из `Sima (Remix)/app_v2.jsx` уже есть 4 слоя и галерея. Дополняем функциями:

| Действие | Где в UI | Что происходит |
|---|---|---|
| Видеть, что готово | цвет блока + счётчик «3/8 задач, 2/3 KPI» в `arch_canvas.jsx` | читается `tasks.md`, `checks.log` |
| Выбрать «реализуй этот блок» | контекстное меню блока + `composer.jsx` | собирается context-pack, отправляется в выбранного агента |
| Видеть рассинхрон | красная подсветка + бейдж «sync✗» | вывод последнего sync report |
| Перейти в подсхему | двойной клик (`subschema.jsx`) | то же самое для дочерних блоков |
| Поправить mission/KPI вручную | `ArchInspector` правая панель | пишет diff в нужный `.md` + history |
| Посмотреть `checks.log` блока | вкладка «проверки» в инспекторе | таблица |
| Посмотреть `decisions.log` / `patterns.md` | вкладка «опыт» в инспекторе | список |
| Запустить ревью продукта | кнопка в галерее | дёргает Codex/Claude в режиме reviewer на context-pack верхнего уровня |
| Добавить правило | редактирование `rules.md` через UI | следующий sync проверит все блоки на новое правило |
| Пометить файл dead | через `files.md` блока | автообновление `files_registry.md` |

## 8. Подключение агентов — все читают одно и то же

| Инструмент | Способ | Что мы кладём |
|---|---|---|
| **Cursor** | `.cursor/hooks.json` (генерим автоматически) + Cursor SDK `Agent.create({ local: { cwd } })` | Хук `beforeShellExecution` инжектит `--context /atlas/blocks/<id>/` в промпт. Хук `afterFileEdit` обновляет `files.md` блока |
| **Claude Code** | `CLAUDE.md` в корне = ссылка на `/atlas/project.md + rules.md`; запуск `claude --print` с `--add-dir /atlas/blocks/<id>` | Subagent `schema-syncer` валидирует изменения против `acceptance.md` |
| **Codex CLI** | `AGENTS.md` ссылается на `/atlas/`. Запуск `codex exec` с тем же context-pack | То же самое, через CLI-флаги |
| **Antigravity / другие** | MCP-сервер Sima Atlas: tools `read_block`, `list_dependencies`, `update_block`, `log_check`, `mark_file_dead` | Любой агент с MCP подключается одной строкой |

Главное: **никто из агентов не получает чат**. Только context-pack. Чат остаётся внутри инструмента и не загрязняет память.

## 9. Где остаётся вектор и зачем

Вектор — **только как backup для исторического поиска**, а не как основная память:
- «найди где мы обсуждали JWT» → роутер из `agi_small/retrieval/router.py` идёт в эпизодический индекс чатов
- результат — список ссылок на сообщения, **не текст** в контекст
- человек открывает в UI и решает, надо ли поднимать в `decisions.log`

Это снижает зависимость от Qdrant/pgvector. На MVP можно обойтись без них вообще.

## 10. Что от `agi_small_tess_test_new` берём, а что — нет

Берём (адаптируем под markdown-хранилище):
- модель `SnapshotNode` (Axis/Character/Memory) → **схема `.md`-файлов в папке блока**
- `snapshot_diff`, `snapshot_dedup` → patch-логика для `.md`
- `pattern_engine`, `principle_extractor`, `wisdom_distiller`, `concept_crystallizer` → дописывание `patterns.md` и `rules.md` из чата
- `conflict_resolver`, `belief_graph_checker`, `ingestion_validator` → sync check
- `gap_detector`, `intelligence_health` → метрика «процент синхронизированных блоков»
- `batch/nightly.py`, `sleep_consolidation`, `axis_evolution` → ночная пересборка
- `core/models.py` (Pydantic) → типы

**Не берём** (или делаем опциональным):
- тяжёлый retrieval pipeline (`rag.py`, `synthesis.py`, `reranker.py`, `ppr.py`, `iterative.py`) — нужен только для backup-поиска по чатам
- Neo4j как основное хранилище — заменяем на файлы + lightweight JSON-граф
- Qdrant как обязательный — только для эпизодического вектора
- `query_hypothesis`, `abductive_reasoner`, `analogy_engine`, `hypothesis_analytics` — это для company-memory use case, для coding-домена избыточно

## 11. От Cursor SDK берём именно это

- `Agent.create({ local: { cwd } })` — единый интерфейс для локального и облачного запуска
- `run.stream()` + `onDelta` (`text-delta`, `tool_call`) — стрим в Sima, чтобы блок «дышал» во время работы агента
- **`.cursor/hooks.json`** — самое ценное: хуки `beforePromptSent`, `afterFileEdit`, `beforeShellExecution` Sima генерирует автоматически и через них:
  - инжектит context-pack
  - перехватывает каждую правку файла → обновляет `files.md`
  - валидирует команды против `rules.md`
- `agents: { ... }` (subagents) — определяем: `schema-syncer`, `verifier`, `wiki-builder`
- MCP-серверы Cursor — Sima сама становится MCP-сервером, чтобы Cursor читал атлас стандартными инструментами

## 12. Что и в каком порядке делать (sync-first phasing)

| Фаза | Цель | Что собираем |
|---|---|---|
| **P1 Atlas-as-files** | Папка `/atlas/` стала источником правды | Schema из `arch_data.js` пишется в `graph.json`. Каждый блок — папка с шаблоном `.md`-файлов. UI Sima Remix читает их |
| **P2 Sync engine** | Кнопка «sync» работает | Перенос `conflict_resolver`, `belief_graph_checker`, `ingestion_validator`. Подсветка блоков. Sync report |
| **P3 Context-pack composer** | Кнопка «реализуй блок» в Sima генерирует точный promt-pack | Сборщик из mission/kpi/logic + neighbors. Отправка в Cursor SDK / Claude Code CLI |
| **P4 Hooks generator** | `.cursor/hooks.json` пишется автоматически | Хуки `afterFileEdit`, `beforePromptSent`, `beforeShellExecution`. Логирование в `checks.log` и `files.md` |
| **P5 MCP-сервер Sima** | Любой агент с MCP видит атлас | Tools: `read_block`, `list_deps`, `update_block`, `log_check`, `sync_check`, `mark_file_dead` |
| **P6 Ingestion из чата** | Полезное из чатов попадает в `patterns.md` / `decisions.log` / `rules.md` | `principle_extractor` + `pattern_engine` + `concept_crystallizer`. Сами чаты в долгую не пишем |
| **P7 Nightly + health** | Ночью считается «процент синхронизированных блоков» | `batch/nightly.py` + `intelligence_health.py` |
| **P8 Wiki + Roadmap auto-render** | `roadmap.md` и страничная вики пересобираются | Простой markdown-ассемблер из `graph.json` + папок |
| **P9 Backup-vector (опционально)** | Поиск «где это обсуждали» по эпизодам чатов | `retrieval/router.py` + Qdrant. Только для UI-поиска, не для context-pack |
| **P10 Multi-agent parity** | Cursor / Claude Code / Codex / Antigravity получают идентичный pack | `AGENTS.md`, `CLAUDE.md`, MCP, hooks — одна модель данных везде |

## 13. Ответы на конкретные требования из твоего уточнения

| Твоё требование | Где оно реализовано в этой структуре |
|---|---|
| Подробная схема всего продукта с блоками и инструкциями | `/atlas/` + Sima Remix UI; каждый блок — папка с инструкциями |
| Проверка синхронизации | §6 Sync check + бейджи в UI + ночной job |
| Человек видит что сделано/не сделано | Цвета блоков, счётчики задач/KPI, `tasks.md`/`checks.log` в инспекторе |
| Человек выбирает что реализовать | Кнопка «реализуй блок» в `composer.jsx`, генерирует context-pack |
| Агенты в Cursor читают именно эти документы | Hooks инжектят `/atlas/blocks/<id>/`; MCP-tools `read_block`; `--add-dir` в Claude Code |
| Не нужна идеальная память — нужна навигация по графу | Вектор понижен до backup; основной поиск — путь по графу |
| Не нужно перечитывать LLM весь чат | Чат не идёт в долгую память; только distillate в `patterns.md` |
| Контекстное окно — только полезное | §3 Context-pack ≈ 4–12k токенов |
| Cursor забыл всё в новой вкладке — не страшно | Достаточно `/atlas/blocks/<id>/`; ничего не теряется |
| Мёртвые файлы | §5 `files_registry.md` |
| «Работает, но не то» | `acceptance.md` + KPI-проверки в `checks.log`, отдельно от unit-тестов |
| Любой инструмент видит продукт одинаково | §8 Multi-agent — все читают один `/atlas/` |
| Тесты, ревью, документация — растут из схемы | §12 P7–P10 |

---

**Итог.** Память живёт **в плоских файлах рядом с кодом**. Граф — это просто `graph.json` плюс структура папок. Sima Remix — визуальный конструктор поверх этих файлов. agi_small даёт нам логику обновления и проверки синхронизации. Cursor SDK + hooks — способ заставить любого агента читать **именно** нужный блок. Никаких «умных RAG» как обязательного слоя — они опциональный backup. Главное свойство: одно изменение → одно место → все агенты и человек видят это одинаково и сразу понимают, что синхронизировано, а что сломано.
